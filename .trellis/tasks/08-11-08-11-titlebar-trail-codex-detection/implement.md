# 实施计划

## 阶段 1：定位与基线

1. 用 CodeGraph 定位标题栏、研究脉络组件、状态源、Codex 设置状态命令和调用路径。
2. 读取前端组件/状态/质量规范、后端错误处理/质量规范和跨层指南。
3. 记录本机 Codex 的真实命令路径、启动器类型和版本输出，复现后端误判条件。
4. 检查现有静态测试、E2E 和 Rust 测试落点，确定最小改动范围。

## 阶段 2：标题栏研究脉络控制

1. 在 `App.tsx` 标题栏中、窗口控制区之前插入唯一研究脉络切换按钮。
2. 将图标、title、aria-label 和按下状态绑定到 `contextOpen`。
3. 简化 `ResearchTrailPanel`：关闭返回 `null`，删除内部折叠入口和多余回调。
4. 删除旧竖向轨道样式，新增标题栏按钮的 hover、active、focus-visible 和选中态。
5. 更新布局/E2E 契约，验证折叠后主内容不留空白、展开后面板恢复。

## 阶段 3：Codex CLI 发现与执行

1. 抽取 CLI 候选生成器、路径规范化/去重逻辑和 Windows 启动器分类。
2. 加入 `CODEX_CLI_PATH`、PATH、npm、WinGet、Scoop、Cargo、`.local/bin`、WindowsApps 资源路径。
3. 对 `.cmd`/`.bat` 使用 `COMSPEC`，对二进制直接执行；统一封装版本和登录状态调用。
4. 让订阅状态接口返回实际命中的版本和现有登录状态，保留原 UI 协议。
5. 添加纯函数单元测试，覆盖带空格路径、重复候选、脚本/二进制分支。

## 阶段 4：一次性质量门禁

1. 运行前端类型检查与静态验证一次。
2. 运行前端单元测试一次、Rust 单元测试一次、GUI E2E 一次（环境满足时）。
3. 运行 Trellis check，检查跨层数据流、旧选择器残留和 Git 范围。
4. 只在测试失败时修复代码；不以同一成功命令反复复测。

## 阶段 5：交付

1. 执行 Tauri release 构建，生成 0.11.0 NSIS 安装器。
2. 静默安装到用户目录并启动客户端，确认进程存在。
3. 更新任务状态、归档 Trellis 任务并写开发日志。
4. Git 提交功能、任务归档和日志；排除用户现有未跟踪文献运行目录。
