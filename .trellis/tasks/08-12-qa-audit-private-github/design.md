# 技术设计

## 发布边界

以当前 Git 仓库为唯一推送源，保留提交历史。远端优先命名为 `origin`；若已存在远端，先核验归属和可见性，不覆盖未知远端。仓库名默认从当前目录 `wireless_charging` 派生；若账户中重名，使用可读且唯一的私有名称。

## 敏感信息审计

1. **配置面**：检查 `.gitignore`、已跟踪的环境文件、Codex/IDE 用户配置、SQLite、日志、缓存和发布产物。
2. **内容面**：优先使用 `gitleaks git --no-banner` 覆盖历史；工具不可用时使用 Git object 遍历与受控正则扫描，结果只输出路径和规则，不输出秘密值。
3. **历史面**：枚举全部 commits/blobs，检查高风险文件名、常见 Token 前缀、私钥头、Bearer/密码赋值和云厂商凭据模式。
4. **体积面**：枚举历史最大 blobs 与当前已跟踪文件，阻止超过 GitHub 100 MiB 的对象。
5. **误报面**：允许文档占位符、环境变量名、测试 fixture 假密钥和安全规则自身，但必须依据上下文确认。

本次扫描命中的短字符串位于 `provider_ids.serpapi`，是论文检索结果标识符，不是 SerpApi API Key；规范文档命中来自普通英文术语。它们保留在文献溯源数据和工程规范中，并作为已人工核验的误报记录，而不是通过宽泛路径白名单跳过后续扫描。

仓库历史包含 Git 提交者邮箱以及少量本机绝对路径。前者属于 Git 提交身份元数据，后者仅出现在开发日志/派生文件中，均不具备认证能力；远端必须保持 PRIVATE。认证凭据、用户级 Codex 配置、环境文件、私钥、证书和本地数据库不属于发布边界。

## GitHub 创建

1. 用 `gh auth status` 确认当前账户及 `repo` 权限。
2. 检查现有 remotes 和同名仓库。
3. 创建私有仓库并添加远端。
4. 推送当前分支和必要标签；不推送构建产物。
5. 使用 `gh repo view --json visibility,url,defaultBranchRef` 复核私密性和默认分支。

## 回滚

- 创建后推送失败：保留私有空仓库和本地提交，修复后重推。
- 可见性异常：立即改回 private 并复核；在确认 private 前不继续上传。
- 扫描发现真实秘密：停止创建/推送，清理工作树和历史并重新扫描。
- 远端配置错误：删除本地错误 remote，不删除未知的远端仓库。
