# 顶部搜索提交与左侧布局调整

## Goal

让顶部全局搜索具备明确、可预期的提交动作，并把搜索与快捷操作组成的命令区统一靠左排列，避免“输入后不知道如何确认”和操作按钮散落在右侧。

## Requirements

1. 搜索框输入内容只更新草稿，不在每个按键后立即请求后端。
2. 按 Enter 或点击明确的“搜索”按钮提交当前内容；两种入口调用同一提交函数。
3. 搜索按钮具备可访问名称和 `data-testid`，搜索中显示忙碌状态并阻止同一草稿重复提交。
4. 清空按钮同时清除草稿、已提交查询与结果；`Ctrl+K` 继续聚焦并选中搜索框。
5. 提交成功后继续进入/刷新文献库结果页，保留最新请求守卫、错误提示和结果分页行为。
6. 顶部搜索框、搜索按钮、新建问答、刷新与研究脉络开关作为一个左对齐命令区；移除把快捷操作推到最右侧的布局。
7. 1366×768 和 1920×1080 不产生横向溢出；窄宽度下允许命令区合理收缩，搜索框保持主要宽度。
8. 不修改 Wiki、Raw 或 Graphify 内容，两个用户 raw 运行目录继续保持未跟踪。

## Acceptance Criteria

- [x] AC1：输入关键词不会立即请求；Enter 和“搜索”按钮都能提交并显示结果。
- [x] AC2：清空按钮清除输入与结果，旧响应不能重新覆盖清空状态。
- [x] AC3：顶部命令区整体靠左，操作按钮紧随搜索区，不再使用右侧自动占位。
- [x] AC4：现有 `Ctrl+K`、搜索错误提示、文献库导航和分页没有回归。
- [x] AC5：Node 状态测试、前端构建、结构验证和严格 GUI E2E 通过。
- [x] AC6：Git 提交仅包含本任务文件，不包含两个 raw 运行目录。
