# 全项目代码缺陷审查与质量报告

## 目标

对 `wireless_charging` 项目的桌面客户端、知识库编译链路、自动检索工具、测试与构建配置执行一次可复核的代码审查，识别真实 bug、回归风险和测试盲区，并产出带证据定位的审查报告。该任务只记录审查结果，不直接修改业务代码。

## 背景与已确认事实

- 项目包含 Windows 桌面客户端：前端位于 `apps/desktop`，Tauri/Rust 后端位于 `apps/desktop/src-tauri`。
- 项目同时包含 `tools/` 下的 Python 知识库编译、论文检索、评估与校验工具，以及 `tests/` 下的自动化测试。
- `graphify-out/graph.json` 已存在；审查前须先用 Graphify 缩小范围，再沿证据定位到源文件和测试。
- 当前 Git 分支为 `master`，审查开始前工作区应保持干净；审查过程只允许新增 Trellis 任务产物和报告。
- 项目 Trellis 使用 inline 模式，不派发实现或检查子代理；主代理负责全部审查、验证和报告。

## 审查范围

1. Rust/Tauri：命令注册、状态管理、数据库/索引读写、增量更新、QA/会话流、错误传播与并发边界。
2. 前端：页面路由、状态同步、Tauri invoke/API 载荷、加载/错误/空状态、窗口和持久化交互。
3. Python 工具：论文检索、PDF/Markdown 转换、frontmatter、路径安全、缓存、下载失败处理和 CLI 参数校验。
4. 测试与构建：单元/集成测试覆盖、测试是否真实断言目标行为、Rust clippy、前端 lint/type-check/build、Python 测试与脚本入口。
5. 配置与跨层契约：命令名、JSON 字段、路径约定、版本/发布脚本、知识库索引与 Graphify 派生物的一致性。

## 审查要求

- 每条候选缺陷必须包含：严重级别、置信度、文件与行号、触发条件/复现步骤、实际影响、根因、现有测试覆盖、建议修复方向。
- 只把可由代码、测试或可重复命令证明的事项列为 bug；推测性风险单独标记为“待验证风险”。
- P0：数据丢失、不可启动、远程执行/密钥泄漏或主流程完全不可用。
- P1：核心功能错误、跨层数据错配、可稳定复现的崩溃/死循环或重要回归。
- P2：边界条件、恢复性、可维护性和测试缺口，不阻断主流程。
- 审查不修改 `raw/` 正文、`wiki/` 正文、`schema/` 或现有业务源代码；如发现问题，只写入本任务报告。
- 报告必须区分“已验证缺陷”“测试失败/环境问题”“待验证风险”，避免把工具限制当成代码 bug。

## 交付物

- `.trellis/tasks/08-09-code-audit-20260809/review-report.md`：最终审查报告。
- 本任务的 `prd.md`、`design.md`、`implement.md`：审查范围、方法和可复现执行计划。
- 如命令产生临时输出，放在系统临时目录或任务目录，不污染知识库正文和 Graphify 主图。

## 验收标准

- [x] 覆盖审查范围内的 Rust、前端、Python 工具、测试/构建和跨层契约。
- [x] 执行并记录适用的 lint、type-check、单元/集成测试和构建检查；跳过项已写明原因。
- [x] 每条 P0/P1 结论均有 `file:line`、复现或静态证明和置信度；无证据内容单独列为待验证风险。
- [x] 报告包含按严重级别排序的发现、未发现项、测试结果、剩余风险和修复优先级建议。
- [x] `git diff --check` 通过，任务外文件没有被修改，审查结论可由其他开发者复核。

## 非目标

- 不在本任务内修复发现的 bug。
- 不重建或覆盖 `graphify-out/graph.json`，除非审查明确发现图文件本身损坏且另行获得批准。
- 不外搜资料，不下载新依赖，不改变用户级 Codex/Trellis 配置。
