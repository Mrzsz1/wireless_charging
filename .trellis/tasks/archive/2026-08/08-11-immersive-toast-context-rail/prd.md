# 沉浸式通知与右栏折叠控件

## 背景

当前应用通知占据主内容顶部整行，会推动页面布局并打断阅读；研究脉络折叠按钮位于右栏顶部，视觉上像独立工具按钮，与边栏关系不清晰。

## 目标

1. 通知改为右上角悬浮的 Obsidian 式 Toast，不参与主内容排版。
2. Toast 显示数秒后进入渐隐动画并自动移除，同时保留手工关闭。
3. 连续通知应安全替换旧通知，重新开始停留与渐隐计时。
4. 研究脉络折叠态仍保持最右侧固定窄栏，但展开按钮应垂直居中嵌入栏内。
5. 按钮与边栏边界、悬停和焦点状态应低干扰、统一，形成沉浸式工作区。

## 交互要求

- Toast 位于标题栏下方、右侧研究脉络区域之前的右上角。
- Toast 不遮挡 Windows 窗口控制按钮，不改变页面宽高或滚动位置。
- 默认停留约 3.6 秒，随后约 0.45 秒淡出并轻微上移。
- 鼠标悬停 Toast 时暂停自动消失；移出后继续计时。
- 手工关闭立即触发短淡出，而不是突兀消失。
- 右栏折叠按钮在窄栏纵向中心附近，采用轻量分隔线/胶囊形态，不使用明显阴影。

## 验收标准

- [x] 通知元素使用固定浮层，不再作为 `.main-workspace` 子元素推挤内容。
- [x] 自动停留、渐隐、手工关闭和悬停暂停均可用。
- [x] 新通知到来会替换旧通知并重置生命周期。
- [x] 折叠栏按钮在 1366×768 和 1920×1080 下垂直居中且位于最右侧栏内。
- [x] 键盘焦点、ARIA live region 与关闭按钮标签完整。
- [x] 构建、静态验证、一次单元测试集合、发布版 GUI E2E、安装版 GUI E2E通过。
- [x] 完成 NSIS 覆盖安装、启动客户端并保存 Git。

## 非目标

- 不改变通知来源、业务文案或后端命令。
- 不实现多条通知队列。
- 不修改研究脉络的数据检索逻辑。
