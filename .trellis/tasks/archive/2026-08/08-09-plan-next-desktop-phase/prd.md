# P5.4 桌面端正确性与恢复可靠性收口（目标版本 0.7.1）

## 目标与用户价值

在 0.7.0 已完成发布硬化和 P1 缺陷修复的基础上，收口代码审查中剩余的 3 个已验证 P2 缺陷与 2 个待验证风险，使用户在快速检索、核心专著阅读、目录增量更新和编译回滚失败场景下得到一致、可恢复、可审计的结果。

本阶段是可靠性补丁阶段，不增加新的研究页面类型，不改变知识库分层，也不扩张 Raw/Wiki 写入权限。目标版本采用补丁版本 `0.7.1`。

## 范围

### R1：全局搜索只接受最新请求

1. 每次查询获得单调递增的请求序号；只有当前最新序号可更新结果、空状态和错误提示。
2. 清空输入时立即失效所有在途请求，旧响应不得重新填充结果。
3. 较旧请求失败时不得清空新查询结果，也不得覆盖当前通知。
4. 不改变既有 `Ctrl+K`、结果数量上限、结果点击和页面打开行为。

### R2：核心专著检索片段正确且 Unicode 安全

1. 标题命中与正文命中分别计算，不再把标题前缀偏移用于正文。
2. 正文片段窗口按字符边界截取，不得在 UTF-8 多字节字符、中文、数学符号或 emoji 中间切断。
3. 正文命中时片段必须包含至少一个查询词；仅标题命中时使用稳定的正文开头摘要，并明确保持章节命中。
4. 空正文、超短正文、查询词位于开头/结尾以及大小写不同均有确定结果。
5. 不降低两本书既有 Recall@5 和 physical-page 锚点质量。

### R3：核心专著章节路径必须受仓库边界约束

1. `chapter-index.json` 的章节路径必须是仓库内相对路径。
2. 拒绝绝对路径、Windows drive/UNC 前缀、`..` 逃逸和通过符号链接/junction 离开仓库根目录的路径。
3. 列表、读取、搜索和索引构建共用同一解析函数，禁止某一入口绕过校验。
4. 路径错误返回包含书 ID、章节 ID 和安全原因的可诊断错误，但不得回显仓库外文件内容。

### R4：多文件回滚具备失败原子性和可审计状态

1. 修改文件系统前完成全部 artifact、目标路径、当前 hash、备份存在性、备份可读性和备份 hash 的预检。
2. 回滚采用“预检 → staging → 应用日志 → 失败反向补偿 → 数据库落账”流程；任何中途失败都必须尝试恢复到回滚前状态。
3. 完全补偿成功时，rollback run 标记 `failed`，原 run 保持 `succeeded`；补偿本身失败时标记 `failed_partial` 并记录精确 artifact 清单。
4. 只有全部文件恢复并完成数据库落账后，rollback run 才标记 `succeeded`，原 run 才标记 `rolled_back`。
5. 所有临时文件必须位于仓库受控备份区或目标同卷临时路径，成功和已补偿失败后均清理；异常退出后的残留可被诊断和安全清理。
6. created、modified、deleted 三类 artifact 均有多文件成功与故障注入覆盖。

### R5：目录监听事件至少处理一次且可恢复

1. watcher 事件在索引事务成功前保持为 in-flight，不得因函数提前返回或 `?` 传播而丢失。
2. 索引失败后保留同一批变化并按有上限的退避策略重试；达到自动重试上限后进入可见的 blocked 状态，用户可手动重试或完整重建。
3. 重试批次需要稳定去重，rename 的旧路径和新路径语义不得丢失。
4. 成功提交后才确认批次并发出 `index_update_completed`；失败发出 `index_update_failed`，包含重试次数、批次大小和脱敏错误。
5. 手动完整重建成功后清理已被覆盖的失败批次，避免重复应用。

### R6：版本、文档与可复核发布记录

1. 将桌面端版本统一更新为 `0.7.1`，同步 `package.json`、`package-lock.json`、`Cargo.toml` 和 `tauri.conf.json`。
2. 在根 `prd.md` 增加 P5.4 阶段说明和真实完成状态；使用 Git 历史恢复 `prd.md:887-896` 的可读 UTF-8 内容，不凭空改写历史数据。
3. 更新 `apps/desktop/README.md` 的故障诊断与验证命令，并追加 `logs/YYYY-MM-DD-*.md` 实施记录。
4. 若知识库正文和水位没有变化，不修改 `wiki/maps/library-status.md`，不重写 `raw/` 或 `wiki/` 正文。

## 非功能与硬边界

1. `wiki/**/*.md` 仍是正文真相；SQLite 和 `graphify-out/` 仍是可重建派生物。
2. 不执行外部论文搜索，不下载或晋升候选，不修改 B 类 `problem` / `idea` 页面。
3. 不新增任意 shell 执行入口，不放宽编译中心 allowlist，不把密钥或用户绝对路径写入日志。
4. 不把本阶段扩张为搜索排序重写、UI 重设计、Graphify 语义补图或新知识库格式迁移。
5. 所有失败必须降级为可见错误和可恢复状态，不得白屏、静默吞错或留下永久 `running` 记录。

## 不在本阶段

- 新增在线协作、云同步、移动端或网站。
- 改造全文检索排序算法或重新定义 95% 评测集。
- 自动编辑 Wiki 正文、自动创建 problem/idea、自动外搜最新文献。
- 生产签名密钥轮换；本阶段只验证既有发布链路未回归。

## 计划结论

下一阶段选择 **P5.4 桌面端正确性与恢复可靠性收口**，优先关闭审查遗留而不是增加新功能。原因是 3 个已验证缺陷和 2 个恢复风险直接影响科研检索可信度、章节证据定位及知识库文件一致性；在这些问题关闭前继续扩展功能会放大状态和恢复成本。
