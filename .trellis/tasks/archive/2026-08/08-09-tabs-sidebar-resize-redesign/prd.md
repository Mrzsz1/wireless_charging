# 顶部页签重设计与侧栏空间伸缩

## 1. 背景

当前 Windows 客户端存在两个明确的界面问题：

1. 主工作区顶部页签采用带完整描边的浏览器式标签，视觉重量偏高，且顶部留白与内容层级不协调。
2. 左侧“我的空间”区域高度完全由 Flex 布局决定，用户只能在内部滚动，不能根据当前目录数量上下调整可视范围。

本任务只调整桌面客户端的工作区页签与“我的空间”区域，不改变知识库、检索、问答、入库和 Graphify 的业务逻辑。

## 2. 产品目标

- 将顶部页签改为轻量、紧凑、符合当前天蓝色视觉体系的“文档轨道”。
- 让“我的空间”区域通过水平拖动柄上下伸缩，并记住用户上次设置。
- 保持现有页签切换、关闭、侧栏折叠、目录展开和页面导航行为不变。
- 鼠标、键盘和高 DPI Windows 环境下均可稳定操作。

## 3. 范围

### 3.1 顶部页签

- 页签轨道高度压缩到约 40–42 px，减少主内容顶部的视觉占用。
- 移除活动页签的完整卡片描边，采用浅色活动背景、加粗文字和 2 px 天蓝色底部指示条。
- 非活动页签保持透明；悬停时使用轻微天蓝色背景。
- 关闭按钮仅在页签处于活动、悬停或键盘聚焦状态时显示，减少噪声。
- 保留多页签水平排列；宽度不足时只在页签轨道内部横向滚动，不让整页产生横向溢出。
- 页签标题过长时省略显示，并通过 `title` 暴露完整标题。
- 当前页签必须有清晰的 `aria-selected` 状态和键盘焦点样式。
- 点击关闭按钮不得误触发页签切换；只剩一个页签时继续沿用当前“不显示关闭按钮”的规则。

### 3.2 “我的空间”伸缩

- 在“我的空间”区域底部、设置/帮助区域上方增加水平拖动柄。
- 向上拖动缩小目录可视区，向下拖动扩大目录可视区。
- 拖动只改变“我的空间”的高度；顶部导航、设置、帮助和主工作区尺寸不得被破坏。
- 目录超出当前高度时继续在“我的空间”区域内部纵向滚动。
- 高度必须受到动态上下限约束：最小高度保证标题和至少约 2–3 行目录可见；最大高度不得覆盖设置/帮助或挤出侧栏边界。
- 拖动期间使用 Pointer Capture，鼠标移出拖动柄后仍能连续调整，释放后正常结束。
- 拖动结果保存到 `localStorage`；重启客户端后恢复。非法、缺失或旧值回退到默认高度。
- 侧栏折叠时隐藏拖动柄；重新展开后恢复上次高度。
- 拖动柄采用 `role="separator"`、`aria-orientation="horizontal"` 及当前值/上下限语义。
- 键盘聚焦拖动柄后，`ArrowUp`/`ArrowDown` 按固定步长缩放，`Home`/`End` 跳到最小/最大值；双击恢复默认高度。
- 拖动时显示明确但克制的天蓝色激活反馈，鼠标指针为 `row-resize`。

## 4. 非目标

- 不改变左侧侧栏整体宽度。
- 不实现页签拖拽排序、页签固定、分组或跨窗口拖动。
- 不改变右侧“研究脉络”面板。
- 不新增第三方 UI、拖拽或状态管理库。
- 不修改 Tauri 后端、知识库原始数据或 `raw/` 内容。

## 5. 兼容与约束

- 继续使用 React、TypeScript、现有 Lucide 图标和 CSS 变量。
- 必须兼容侧栏展开/折叠、1366×768 与 1920×1080 两种验收视口。
- 不能产生文档级横向滚动条或遮挡底部状态栏。
- 本地存储失败时界面仍可操作，不向用户显示阻断性错误。
- 遵循 `.trellis/spec/frontend/` 的组件、状态、类型和质量规范。

## 6. 验收标准

### 页签视觉与交互

- [x] 页签栏高度与上下留白明显小于当前实现，内容标题不再被厚重页签框抢占视觉焦点。
- [x] 非活动关闭按钮默认不可见，在悬停、活动或键盘聚焦时出现。
- [x] 切换、关闭、多页签横向溢出、最后一个页签保护行为均正常。
- [x] 页签拥有正确的 tablist/tab ARIA 结构和可见键盘焦点。

## 7. 已确认产品决策

- 顶部页签采用“轻量文档轨道”，而不是圆角胶囊或传统浏览器标签。
- 活动状态采用现有天蓝色体系。
- “我的空间”使用水平拖动柄上下伸缩，并持久化用户高度。
