# 实现上下文相关研究脉络证据链

## 目标

把 Windows 客户端右侧“研究脉络”从目录前几项的静态占位展示，升级为由**当前页面或当前研究问题驱动**的真实证据链与相关方法面板。用户应当能够判断每条内容为什么相关、来自哪个通道、如何回到原文，并能手工补充或固定证据。

目标版本：`0.8.0`。

## 已确认现状

1. `apps/desktop/src/App.tsx:475-476` 把 `catalog.slice(0, 5)` 当作证据链，并把前四个 `method` 页面当作相关方法；当前编号只是目录顺序，不是相关度。
2. `apps/desktop/src/App.tsx:595-599` 直接渲染上述数组；“添加证据”只跳转问答页，“查看完整脉络图”只切换到 Graphify 页面。
3. 页面详情已有正文、frontmatter、出链和反向链接能力：`PageDetail.links`、`getBacklinks`，见 `apps/desktop/src/types.ts:125-151`。
4. 客户端已有 Wiki FTS5、核心书籍 FTS5、Graphify 节点检索和混合排序，见 `apps/desktop/src-tauri/src/qa.rs:584-970`；问答证据类型已能定位 Wiki、书籍章节和图谱节点，见 `apps/desktop/src/types.ts:263-294`。
5. `AskView` 在检索完成事件和历史会话加载后持有本轮证据，但没有把当前问题/证据同步给全局研究脉络面板，见 `apps/desktop/src/features/qa/AskView.tsx:60-177`。
6. Graphify 已提供 overview、neighbors 和 path 命令，客户端可以打开 Wiki 页面、核心书籍章节和图谱视图。
7. 当前知识库写入边界保持不变：`raw/` 和 `wiki/` 正文只读；本功能只读检索派生索引和 `graphify-out/graph.json`。

## 产品规则

### R1：上下文锚点必须真实且可见

1. 当前打开 Wiki 页面时，锚点为该页面的 `pageId + title`。
2. 智能问答页发起问题或打开历史会话时，锚点为最近一轮有效用户问题；面板结果必须和该轮问题对应。
3. 文献库/方法库存在非空搜索词时，可使用稳定后的搜索词作为临时锚点；空查询不生成伪证据。
4. Dashboard、设置、编译中心等没有研究上下文的页面显示“打开页面或提出问题后生成脉络”，不得回退到目录前五项。
5. 面板标题下显示“基于：锚点标题/问题摘要”，让用户知道当前证据链针对什么生成。

### R2：证据链必须来自可审计的混合检索

1. 页面锚点的候选来源按以下通道合并：
   - 页面出链；
   - 页面反向链接；
   - Wiki FTS5（标题、摘要、正文、关键词）；
   - 两本核心专著章节 FTS5；
   - Graphify 锚点节点的一跳邻居和可解释关系。
2. 问题/搜索锚点复用现有中英词项扩展、Wiki FTS5、核心书籍和 Graphify 通道。
3. 同一 Wiki 页面、同一书籍章节或同一图谱节点必须去重；页面自身不得作为自己的推荐证据。
4. 默认显示 5 条自动证据；候选不足时如实显示，不得用无关页面补满。
5. 每条证据必须带：真实排名、来源类型、关系类型、归一化相关度、检索理由、摘要/片段、可定位来源。
6. Graphify 只提供关系提示；其条目必须显示“需回到 Wiki/原文核验”，不得伪装成正文事实。
7. 至少保留一个有分候选的 Wiki 结果和一个核心书籍结果；某通道无命中时显示降级信息，不伪造多源覆盖。

### R3：相关方法必须独立排序

1. “相关方法”只展示 `page_type=method` 的页面，不再简单取方法目录前四项。
2. 排序信号包括：与锚点直接链接、FTS 命中、Graphify 邻接、方法族/场景/目标/约束字段重合。
3. 默认最多显示 4 条；每条显示方法族、关系说明、相关度和摘要。
4. 没有方法命中时显示明确空状态，并提供“在方法库中搜索当前锚点”的入口。

### R4：面板交互必须可用而非装饰

1. 点击 Wiki 证据打开对应页面；点击书籍证据打开准确章节；点击图谱提示聚焦对应节点。
2. “查看完整脉络图”打开 Graphify 视图并尽量聚焦当前锚点节点，而不是只打开无上下文的总图。
3. “添加证据”打开本地证据选择器，可搜索 Wiki 页面和核心书籍章节，并将条目固定到当前锚点。
4. 手工固定只保存在客户端派生状态中，按 `repository + contextKey` 隔离；不得写入 Wiki/Raw，也不得改变自动排名。
5. 固定证据可取消；固定项显示“手工固定”，与自动排名明显区分。
6. 面板支持手动刷新、收起/展开，并保留现有天蓝色视觉语言。

### R5：状态、并发与降级必须稳定

1. 上下文变化后自动刷新；快速切换标签或连续输入搜索词时，只有最新请求可以发布结果。
2. 问题草稿输入期间不逐键检索；只在提交问题、打开历史会话或搜索词稳定后刷新。
3. 结果按 `repository identity + contextKey + repositoryGeneration + graphRefreshVersion` 缓存；知识库或 Graphify 更新后旧缓存失效。
4. 仓库切换必须清空旧仓库上下文、结果和固定证据视图，禁止跨库串线。
5. 加载、空结果、部分通道降级和完整失败具有不同界面；失败提供重试，不得回退静态目录项。
6. 没有 `graph.json` 时 Wiki/书籍结果继续工作；没有书籍索引时 Wiki/Graphify 继续工作。

### R6：边界与可信度

1. 默认完全离线，不调用外部搜索，也不要求 Luna API Key。
2. 不引入远程 embedding 服务；本阶段采用结构关系 + FTS5 + 中英词项扩展的确定性混合检索。
3. 不修改 `raw/`、`wiki/`、`schema/` 正文，不新增页面类型，不改变 B 类页面确认闸门。
4. 不把 Graphify 派生图当作唯一真相；所有可定位 Wiki/书籍证据优先打开正文。
5. 本地存储损坏、旧 schema 或无效固定项必须安全忽略并自动清理。

### R7：质量与发布

1. 新增 Rust 检索单元测试、TypeScript 状态/排序测试、结构门禁和严格 GUI E2E。
2. 保持现有前端、Rust、Python、Wiki 10 问、两书 295 条 Recall@5 门禁通过。
3. 发布版本统一更新为 `0.8.0`，生成 release EXE、MSI、NSIS 并记录 SHA-256。
4. 更新根 PRD、桌面 README、实施日志、Trellis spec 和 Graphify 派生图。

## 验收标准

- [ ] AC1：打开任意 Wiki 页面后，面板显示该页面为当前锚点，内容不再等于 `catalog.slice(0, 5)`。
- [ ] AC2：打开 `Algorithmic Game Theory` 页面时，证据链排除页面自身，并至少返回真实 Wiki 链接、相关书籍章节或 Graphify 邻接中的有效候选。
- [ ] AC3：问答提交“有没有什么解决办法”后，研究脉络按该问题刷新，并保留至少一个 Wiki 与一个核心书籍候选（若相应索引存在）。
- [ ] AC4：证据排名由确定性分数产生；连续两次相同请求返回相同顺序，编号等于真实排名。
- [ ] AC5：每条证据展示来源、关系、相关度、检索理由和定位信息；Graphify 提示具有核验标识。
- [ ] AC6：相关方法全部为 `method` 页面，且其排序与当前锚点有关；无命中时不显示随机方法。
- [ ] AC7：Wiki、书籍和图谱条目分别能打开正确页面、章节和聚焦节点。
- [ ] AC8：“添加证据”能搜索并固定 Wiki/书籍条目；重启后同一仓库同一上下文仍存在，切库后不串线。
- [ ] AC9：快速切换两个页面时，较早请求即使后返回也不能覆盖较新上下文。
- [ ] AC10：Graphify 缺失、书籍索引缺失和完整检索失败分别产生正确降级/错误状态，均不回退目录前五项。
- [ ] AC11：1366×768 与 1920×1080 下侧栏可滚动、主要操作可达、无横向溢出。
- [ ] AC12：Rust/TypeScript/Python/Wiki/两书门禁全部通过；`raw/`、`wiki/` 正文无修改。
- [ ] AC13：生成 0.8.0 EXE、MSI、NSIS，严格 GUI 与安装/卸载测试无关键 `SKIP`，Git 工作树干净。

## 范围外

- 外网查新、在线论文下载或自动写入知识库。
- 云端向量数据库、远程 embedding 服务或新模型依赖。
- 自动生成新的 synthesis/problem/idea 页面。
- 多用户同步、云端固定证据同步或协同批注。
- 改写核心问答提示词的学术结论生成规则。
