# 智能问答动态思考加载

## Goal

把智能问答处理中偏静态的步骤卡升级为持续可感知的加载过程，让用户明确系统仍在工作、当前处于哪个真实阶段以及已经等待多久。

## Requirements

- 只使用 `retrieval_started`、`retrieval_completed`、首个 token、`validation_started` 等真实事件决定阶段，不伪造模型内部步骤或百分比。
- 活动阶段持续呈现流动轨道、脉冲状态、动态省略号和实时耗时。
- 已完成步骤逐步点亮，等待步骤保持弱化，任一时刻最多一个活动步骤。
- 首个 token 到达后切换为“正在生成回答”，并显示流式光标；不渲染未完成的结构化 JSON。
- 校验阶段显示“正在检查引用与完整性”。
- 完成、失败、取消和知识库切换时清理所有计时与瞬态加载状态。
- 动画必须支持 `prefers-reduced-motion`，屏幕阅读器只在真实阶段变化时收到信息，不因省略号动画重复播报。

## Acceptance Criteria

- [x] 检索、Thinking、生成和校验阶段均有持续动态加载反馈。
- [x] 活动步骤随真实事件切换，且任一时刻只有一个 active。
- [x] Thinking 计时保持单调并在终态清理。
- [x] 结构化 JSON 流不会作为回答正文显示。
- [x] 减少动态效果和窄屏布局可用。
- [x] 前端全测、构建及 Tauri release 编译通过。

## Out of Scope

- 展示模型 chain-of-thought。
- 为 Provider 推理构造虚假百分比或预计完成时间。
- 修改后端回答事件协议。
