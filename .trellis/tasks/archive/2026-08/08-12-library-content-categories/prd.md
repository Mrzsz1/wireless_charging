# 文献库内容分类

## 目标

把客户端“文献库”中混排的 Wiki 页面按内容类型提供清晰、可见、可计数的分类筛选，并将内部类型 `map` 的用户界面文案统一为“知识地图”。

## 背景

当前 `LibraryView` 把 75 个 Wiki 页面直接混排，只在卡片左侧显示内部 `pageType`。用户会连续看到 map、method、source 等不同性质内容，难以建立阅读预期。当前真实类型为：23 source、20 method、8 map、7 concept、7 synthesis、4 objective、4 system-model、1 dataset-or-sim、1 problem。

## 需求

1. 文献库顶部新增内容分类栏，提供：全部、论文文献、方法、综述、概念、系统模型、优化目标、数据与实验、研究问题、知识地图。
2. 每个分类显示当前可见数据集中的数量；选择后仅显示对应 `pageType`。
3. `map` 在所有文献库卡片和分类文案中显示为“知识地图”，不暴露英文内部类型名。
4. 分类与搜索、年份、状态、排序和分页联动；切换分类必须回到第一页，结果收缩时页码继续自动收敛。
5. “方法库”入口保持独立，并强制只显示 method，不出现通用分类栏或其他页面类型。
6. 未识别的新页面类型仍可在“全部”中显示，卡片使用可读的兜底文案，不因分类功能丢失数据。
7. 保持现有浅色天蓝视觉系统、紧凑布局和键盘/辅助功能语义。
8. 同步发布 Windows 客户端 0.12.2，生成并安装 NSIS，保留两个既有 raw discovery 未跟踪目录。

## 验收标准

- [x] 文献库分类总数与当前 75 页基线一致，各已知类型计数正确。
- [x] 点击“知识地图”只显示 8 个 map 页面，卡片类型显示“知识地图”。
- [x] 搜索结果可继续按分类过滤，切换分类后分页回到第 1 页。
- [x] 方法库只显示 method 页面。
- [x] 分类控件有 `aria-pressed`、稳定 test id 和清晰焦点态。
- [x] 类型过滤单元测试、前端 build、P5/GUI E2E、Rust/Python必要回归通过。
- [x] 0.12.2 安装包构建、静默安装、版本与启动探针通过。
- [x] Git 提交、Trellis 归档和 journal 完成；raw 正文与 `schema/vocab.yaml` 未修改。

## 不在范围

- 不改变 Wiki frontmatter 类型定义。
- 不移动或重命名 Wiki 文件。
- 不修改后端 SQLite schema 或搜索排名。
- 不新增/改写 problem、idea 或正式词表。
