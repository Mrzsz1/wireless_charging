# 智能问答 P0-P1 完成

## 目标

完成 2026-08-12 审查确认的智能问答全部 P0 与 P1，使客户端从“单轮生成套在多轮界面上”升级为具备真实会话上下文、意图感知检索、后端引用校验、仓库隔离和明确失败语义的可靠问答链路。

## P0 范围

1. **真实多轮上下文**：同一会话的最近有效 user/assistant 消息进入模型 Prompt；限制轮数与字符量；不把 failed/cancelled 临时消息、错误文本或证据全文重复塞入历史。
2. **后端引用完整性**：对最终回答解析 `[E#]`，拒绝未知引用；计算引用集合、引用精度和最低覆盖状态。远程模型回答包含事实段落却无有效引用时不作为成功回答持久化；离线证据模板保持可验证。
3. **意图感知检索**：`solve`、`novelty`、`relationship` 控制候选来源配额、类型加权和排序理由，而非只写入 Prompt；所有模式仍以 Wiki/论文正文为事实源，Graphify 仅作关系提示。
4. **仓库切换隔离**：每个请求携带 repository ID；后端在准备、生成和持久化前复核当前仓库；前端使用 repository generation 丢弃旧事件，并在仓库变化时主动取消在途请求。

## P1 范围

1. 每条 assistant 消息的“重试”绑定其前一条 user 消息，而不是会话最后一个问题。
2. 取消/失败时移除对应乐观 user 消息和流式 assistant 草稿，或显示明确失败状态；不得留下看似已发送但未持久化的幽灵消息。
3. Codex 状态只在 Codex 模式或设置页显式刷新时探测；离线/API 模式不承担 Codex CLI 探测延迟；同一问答请求不重复探测。
4. Graphify 检索使用节点文本、邻居/边、社区和来源位置；无可回链 Wiki/原文位置的 graph 节点不得作为最终可引用证据。
5. Graphify `sourcePath` 规范化为可打开的仓库相对 Wiki page ID/path，打开来源稳定工作。
6. 远程 provider 失败发送结构化 `failed` 事件并保存失败消息状态；不得自动伪装为普通 completed 离线回答。用户主动选择“仅离线证据”时才保存 offline completed。

## 数据与兼容要求

- 既有会话数据库原位兼容；允许新增可空字段或迁移，但不得删除历史。
- `AskRequest`、事件 DTO 和持久化状态必须在 Rust、TypeScript 与 IPC 服务层一致。
- 回答仍使用 `[E#]`，并保留库水位、证据定位和知识库隔离。
- 不读取 Codex token/cookie，不写入凭据，不修改 Raw/Wiki/Schema 正文，不默认外搜。

## P2 待定（本阶段不实施）

- Markdown/KaTeX/表格/代码块完整渲染与证据抽屉重设计。
- 会话服务端分页/导出、更多 Provider Adapter、外部论文检索。
- citation precision/coverage、unsupported claim rate、nDCG 与端到端延迟仪表盘的长期评测体系。

## 验收标准

- [x] 多轮测试证明后续问题 Prompt 包含同会话有效历史，且受轮数/字符预算限制。
- [x] 未知 `[E#]`、无引用事实回答无法保存为成功；合法引用返回结构化校验摘要。
- [x] 三种意图产生可观察且有测试覆盖的来源配额/排序差异。
- [x] 仓库切换会取消/隔离旧请求，旧事件与旧结果不进入新仓库 UI/DB。
- [x] 任意历史 assistant 的重试使用其相邻 user 问题。
- [x] 取消/失败无幽灵消息；远程失败与主动离线 completed 可区分。
- [x] 离线/API 模式不调用 Codex 状态探测；Codex 模式每次请求最多一次。
- [x] Graphify 候选具备边/邻居关系理由和可打开来源；无来源节点被过滤。
- [x] Rust 测试、前端 QA 状态测试、TypeScript 构建和项目既有 P3/P5 门禁通过。
- [x] 变更提交并推送到私有 GitHub `master`。

- 不自动外搜、不改变文献晋升治理、不创建 B 类页面。
