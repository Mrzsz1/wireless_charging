# Markdown 科研混合 Agentic RAG 重构

## Goal

把当前以整页/整章 FTS、单向量缓存、固定结果数量停止和结构化回答校验为主的智能问答，重构为面向个人科研使用的 Markdown-first 混合 RAG：系统应能从论文、专著、Wiki 和知识图中稳定召回实际存在的内容，进行有限多轮补查，生成自然中文回答，并在回答末尾追加可点击、可回到 Markdown 原文的真实证据。

## User Value

- 用户换一种问法、换一个领域词或同时询问“论文或书籍”时，不需要为单个关键词添加专用规则。
- 对指定书籍、论文或开放来源范围的问题，系统能证明各请求通道确实执行过，而不是被其他通道的若干弱结果提前停止。
- 回答区分库内证据和模型补充；证据不足不阻断自然回答，但不得把模型推断伪装成知识库事实。
- 用户点击回答末尾的短证据链接，可直接打开对应 Markdown 文档并定位到稳定内容块。
- 检索、生成、模型与索引版本可审计，但完整审计信息默认不占用回答页面。

## Confirmed Product Decisions

1. Markdown 是问答正文的唯一必需来源；PDF、印刷页码和物理页码均为可选兼容字段，不得成为入库、检索或引用的前置条件。
2. 稳定定位主键为 `documentId + headingPath + blockId`；行号只作为辅助定位和人工核验信息。
3. 索引粒度至少包含文档、章节/小节和语义段落；不再以“整章正文前 2400 字生成一个向量”作为唯一语义表示。
4. 内容角色至少覆盖 `abstract`、`research_background`、`research_motivation`、`research_objective`、`related_work`、`problem_definition`、`model`、`method`、`algorithm`、`theory`、`proof`、`experiment`、`result`、`limitation`、`conclusion`、`reference` 和 `general_content`。
5. 问题理解不得依赖四种或其他固定中文意图词表；Provider 只生成开放的检索契约，代码负责边界、归一化和执行。
6. 检索采用标题/别名、FTS/BM25、稠密向量、元数据过滤和可选知识图导航的混合架构；知识图只产生候选或关系提示，不能单独作为正文事实。
7. 不使用“结果数量达到 N 条即充分”的硬停止。系统记录覆盖面、已尝试通道、新增收益和缺口，再决定是否继续，最多进行有限补查。
8. 最终回答由模型直接生成自然 Markdown；不再要求每段或每个 claim 携带证据，也不要求模型输出复杂回答 JSON。
9. 真实证据附录由后端根据本轮实际选中证据确定性追加，模型不得自行生成文件路径、证据 ID 或定位信息。
10. 不实现引用—结论语义蕴含判定；只保留来源存在性、定位有效性、证据附录完整性和零证据边界等结构性校验。
11. 多轮对话不设固定轮数上限；达到模型上下文预算时压缩较早的已验证问答，并重新计算上下文预算。
12. 默认不外搜；本任务只重构当前知识库的本地/已配置存储检索，不改变外搜授权规则。
13. 不新增面向用户的“数据集说明”页面或强制字段；评测夹具只服务回归验证。

## Requirements

### R1 — Markdown 统一语料契约

- 统一表示 Wiki 页面、论文 Markdown、专著 Markdown 和章节文件。
- 解析 frontmatter、标题树、段落、列表、公式、代码块和表格边界。
- 为每个内容块保存文档类型、标题、别名、作者、年份、标签、标题路径、内容角色、稳定 block ID、行号和内容哈希。
- 重复的转换稿或 `full.md` 不得造成同一来源被重复计分。

### R2 — 多粒度索引与增量更新

- 文档级表示用于来源识别和书名/论文名定位。
- 章节/小节级表示用于主题和方法定位。
- 语义段落级表示用于精确证据召回。
- 内容哈希未变化时复用已有索引与向量；变化时只重建受影响文档。

### R3 — 多语言实体与别名

- 支持书籍、论文、术语和典型问题的中英文别名。
- `近似算法` 必须能解析到 `Approximation Algorithms`，但实现不能针对该词硬编码特例。
- 别名来源必须可审计：frontmatter、现有 Wiki 链接/标题、模型提议或用户配置。

### R4 — 向量存储能力

- 定义与检索编排解耦的向量存储接口。
- 配置远程 PostgreSQL + pgvector 时可持久化和搜索多粒度 embedding。
- 保留离线可工作的本地向量缓存/词法检索降级；远程不可用不得导致整个问答失败。
- 模型、维度、内容哈希、索引版本和存储状态必须可检查。

### R5 — 开放检索契约

- 契约表达 `scope.mode`、显式来源、请求来源类型、核心概念、别名、相关问题、回答面和预算。
- Provider 原生 JSON Schema 只用于检索契约，不用于最终回答正文。
- Schema 解析失败时使用保守的开放检索降级，不得退化为固定 `solve` + 最少四条的旧行为。

### R6 — 独立检索通道与融合

- Wiki、论文 Markdown、书籍 Markdown、语义向量和知识图通道独立执行并记录 attempted/succeeded/hit count。
- 指定来源时先解析来源身份并下推元数据过滤；开放问题按 requestedKinds 分配通道配额。
- 候选使用稳定去重键，经 RRF 融合并由本地或可配置 reranker 重排。
- 同一文档的多个近重复块不能挤掉其他来源，但关键文档的多个互补小节允许同时入选。

### R7 — 有限 Agentic 补查

- 首轮后依据通道尝试情况、来源覆盖、回答面覆盖、冲突和新增收益判断是否补查。
- 补查词由 LLM 生成，代码进行去重、数量/长度限制、来源约束和审计。
- 默认最多两轮补查；超时、取消和上下文预算可提前终止。
- 停止原因必须记录，例如 `all_requested_channels_attempted`、`no_new_gain`、`budget_exhausted` 或 `cancelled`。

### R8 — 自然回答与证据附录

- 模型接收问题、经过预算控制的多轮历史和选中证据，直接输出自然 Markdown。
- 提示词要求准确说明证据边界，不强制固定中文章节标题或固定 claim 数。
- 后端追加 `参考证据`，每条只显示短标题、来源类型和标题路径；详细文件名不直接展示。
- 零证据时允许模型一般知识补充，但必须有明确的未核验标识且不生成伪证据。

### R9 — Markdown 深链

- 每条证据链接能回到 Wiki、论文 Markdown 或专著 Markdown。
- 优先按 block ID 定位；block 不存在时按 heading path；最后才按行号。
- 旧会话的证据快照在文档编辑后仍能解释失效原因，而不是打开错误位置。

### R10 — 多轮上下文与审计

- 最近消息与压缩记忆共享统一 token 预算，不使用固定 1–8 轮上限。
- 只有完成且通过最低结构校验的回答进入后续可信上下文。
- 审计保存问题、检索契约、每轮查询、通道状态、候选、选中证据、模型/embedding/索引版本、停止原因和最终回答。
- 默认 UI 只显示回答、证据和简要检索范围；完整审计按需展开或导出。

### R11 — 兼容与迁移

- 现有 SQLite 会话和消息不得在重建知识索引时丢失。
- 旧的 `pages`、`paper_sections`、`books`、`book_chapters` 和 LUNAVEC1 缓存应有明确迁移或兼容期。
- 迁移可以回滚；索引是可重建派生物，Markdown 正文不得被重写。

## Acceptance Criteria

- [x] AC1：`raw/canonical/**/*.md`、`wiki/**/*.md` 和核心专著章节均进入统一文档/内容块索引，且不会把同一论文的重复转换稿计为两份来源。
- [x] AC2：每个选中证据都有非空 `documentId`、`headingPath`、`blockId`、内容哈希和可解析 Markdown 路径；PDF 字段为空时仍可完整问答和跳转。
- [x] AC3：文档、章节/小节和语义段落三种粒度均生成可检查 embedding；索引重跑对未变内容不重复计算。
- [x] AC4：问题“在近似算法这本书里面有没有关于移动路径规划的算法”能召回目标书的 TSP/Euclidean TSP 相关章节，不被无关无线充电论文提前停止。
- [x] AC5：问题“有没有文献或者哪本书涉及移动路径规划”会分别尝试 paper 和 book 通道，并在审计中记录两者状态；结果总数不替代通道覆盖。
- [x] AC6：换用未在代码中出现的新术语时，检索流程仍通过语义、别名和 LLM 查询扩展运行，不要求新增关键词特判。
- [x] AC7：Planner 失败、语义模型未部署、远程 pgvector 离线或 Graphify 缺失时均 fail-soft，并在诊断中明确降级通道。
- [x] AC8：最终用户看到自然 Markdown 回答；回答末尾的证据由后端生成，每个链接只能引用本轮已选中且仍可定位的 Markdown 块。
- [x] AC9：最终回答不再因缺少固定中文章节名、固定 claim 数或逐段 `[E#]` 而失败；未知证据 ID 和越界路径仍被拒绝。
- [x] AC10：模型补充与库内事实视觉和数据状态可区分；零证据回答不会进入后续可信上下文。
- [x] AC11：长会话达到上下文阈值后触发压缩并重新计算预算，历史轮数不受固定数量限制。
- [x] AC12：现有会话、设置、模型部署检查、取消/超时和后台任务行为不回归。
- [x] AC13：各子任务完成其局部测试；最终集成通过 Rust、前端构建、目标检索回归和 Tauri release 编译。

## Out of Scope

- 引用与结论的语义蕴含自动判定。
- 默认公网搜索、自动下载新论文或改变现有外搜授权规则。
- 修改 `raw/` Markdown 正文、自动创建 problem/idea 页面或修改正式词表。
- 将 Graphify 变成正文真相或用 Graphify Wiki 覆盖当前 Wiki。
- 强制恢复 PDF、印刷页码或物理页码。
- 面向用户增加数据集说明模块。
