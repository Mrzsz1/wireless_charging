# 证据侧栏轮次隔离

## Goal

新问题检索期间保留上一轮证据供用户查看，同时保证上一轮证据不会被误认为或复用为本轮证据。

## Requirements

- 提交新问题时不清空已经展示的证据、水位和检索诊断。
- 新请求开始后，侧栏明确显示“上一轮证据 · 不参与本轮回答”。
- 收到本轮 `retrieval_completed` 后，按 requestId 原子替换为本轮证据。
- 本轮失败或取消时继续保留上一轮证据展示。
- 历史证据只影响 UI；后端 Prompt、JSON Schema、校验和审计保持 request-scoped。
- 历史消息自身的引用仍使用 `message.evidence` 打开，不依赖侧栏当前快照。

## Acceptance Criteria

- [ ] 新问题检索中上一轮证据仍可见且带隔离标识。
- [ ] 本轮检索完成后侧栏只显示本轮证据。
- [ ] 失败/取消不会清空上一轮证据。
- [ ] 仓库切换和新会话会清空证据，避免跨仓库或跨会话泄漏。
- [ ] 前端状态回归测试覆盖上述行为。
