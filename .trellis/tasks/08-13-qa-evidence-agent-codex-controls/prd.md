# 多轮证据分级 Agent 与 Codex 聊天模型控制

## Goal

把当前“一次检索后严格通过或失败”的智能问答升级为可迭代检索的本地知识库 Agent：优先用库内证据回答，证据不足时仍提供清晰标识为“可能不准确”的模型补充；同时修复 Codex 订阅生成频繁超时，并把准确的模型/推理强度控制迁移到聊天输入区，保持现有软件视觉语言。

## Background

- 当前已具备多轮会话、可信历史隔离、多通道检索、引用语法/覆盖校验、零证据未验证回答、Codex 模型缓存读取和 Thinking 阶段。
- 当前只执行一轮查询；`query_terms` 仍含“波干扰、已知轨迹、城市路口”等问题级短语特例，换一种表达可能再次漏召回。
- 有证据时只允许全部事实逐句引用，否则整轮 `CITATION_VALIDATION_FAILED`；尚不能在同一回答中区分“库内验证内容”和“模型补充”。
- Codex 执行把 `timeoutSeconds` 当作从进程启动起的绝对总时限，默认 90 秒。高推理强度即使持续输出 JSONL 活动，也会被固定时限终止。
- 模型目录已经从本机 Codex `config.toml` 和 `models_cache.json` 投影，但控制位于设置页，聊天输入区只有突兀的标题状态胶囊；用户期望类似 Codex 的输入区模型/推理强度选择。
- 本机目录当前包含 `gpt-5.6-sol/terra/luna` 等 list-visible 模型，并为每个模型提供默认与支持的 reasoning levels；这些元数据应作为单一真相，不维护静态模型清单。

## Requirements

### R1 — 通用多轮检索 Agent

- 每次请求最多执行三轮有界检索：原始/组合词检索、索引候选驱动的查询扩展、必要时的中文片段/词形回退。
- 每轮仍检索 Wiki、论文、Wiki 关联论文、核心书籍和 Graphify；融合、去重、来源保护和证据预算继续生效。
- Agent 根据证据数量、意图所需来源类型、新增候选收益和是否产生新扩展词确定继续或停止；不得无界循环。
- 删除“波干扰、已知轨迹、充电费、城市路口”等问题级整句特例；保留可组合的领域概念词映射，并由已召回标题/元数据生成受控扩展。
- 任意主题均走同一规划器；不得用新增测试问题的完整短语作为专用分支。
- 检索诊断记录轮次、停止原因、候选增益和各通道聚合计数，但不暴露问题、查询词、片段、路径或凭据。

### R2 — 已验证内容与模型补充分级输出

- 有证据时允许回答同时包含：库内证据支持的事实，以及独立的“模型补充（可能不准确）”区域。
- 库内事实继续逐句绑定本轮有效非 Graphify `[E#]`；未知编号、Graphify-only 引用和未标识的无引用事实仍失败关闭。
- 模型补充区域不得使用 `[E#]`、wikilink、论文行号或书籍页码，必须明确说明其来自模型一般知识且可能不准确。
- 新增 `mixed` grounding 状态及结构化计数，使 UI 能显示已引用声明数、模型补充声明数和边界；纯证据回答仍为 `supported`，零证据仍为 `unverified`。
- `mixed` 消息可供用户查看和追问，但只有用户问题与已验证内容可进入后续可信上下文；模型补充文本不得进入压缩记忆、指代实体抽取或检索改写。
- 保留完整回答用于历史展示和审计包；另持久化/投影可信上下文内容，避免后续模型把推测当事实。

### R3 — 明确排除语义蕴含审计

- 本任务不实现引用片段是否在语义上蕴含结论的 NLI/LLM 审计。
- `entailmentChecked` 保持 `false`，UI 必须继续说明“语义未自动核验”。
- 不降低引用真实性、当前轮编号、同句覆盖或 Graphify 边界。

### R4 — Codex 超时语义修复

- Codex CLI 生成不再仅按进程启动后的固定 90 秒终止。
- 将配置超时解释为“无活动超时”：收到任意有效 JSONL 事件或文本增量即刷新活动时间；另设有界总时限防止进程永久占用。
- 默认值适合高/xhigh/max 等较长推理；停止按钮在任何等待阶段仍立即终止进程树。
- 错误码区分无活动超时和绝对总超时，并保存可重试失败交换；不得把部分输出保存为完成回答。
- 兼容 API provider 保持其 HTTP 超时语义，不因 Codex 修复而静默改变。

### R5 — 聊天输入区模型与推理强度控制

- 在聊天 composer 底部加入模型与推理强度选择器，交互层级和布局参考 Codex：紧凑、低对比、无额外大卡片。
- 模型列表来自本机 Codex list-visible 模型目录；推理强度严格跟随当前模型支持集合和默认值。
- 支持“自动跟随 Codex”与显式选择；当前请求必须携带选择快照，避免设置保存与发送之间的竞态。
- 选择结果作为后续请求默认值持久化；切换模型时若当前 effort 不受支持则回到自动或该模型默认值。
- 聊天标题只保留简洁的 provider readiness，不重复展示长模型状态；详细模型选择归 composer。
- Codex 不可用、目录缺失/损坏、模型不在目录和刷新失败均 fail-soft，且不泄漏 token、cookie、API Key 或完整配置。
- 设置页移除重复的 Codex 模型/推理强度控件，保留 provider、登录/刷新、API 和上下文等高级设置。

### R6 — UI 风格与可访问性

- 复用现有蓝灰色、细边框、小圆角和紧凑字号；禁止独立悬浮大面板、强阴影、纯黑圆形控件或与软件不一致的高饱和强调。
- 模型/effort 菜单具备键盘焦点、禁用态、完整 title/aria 标签，窄屏可收缩且不挤压停止/发送按钮。
- Thinking 阶段增加“改写查询/再次检索”真实状态，不展示模型隐藏思维链；耗时与取消清理继续正确。

### R7 — 兼容与质量

- Rust DTO、Tauri 请求/事件、TypeScript 类型、SQLite 迁移、历史水合、审计包和 UI 一致升级；新字段使用默认值兼容旧记录。
- 保留 request/repository 隔离、取消、失败交换、输出解析、Markdown 引用投影、答案完整性和零证据规则。
- 不修改 `raw/`、`wiki/`、`schema/vocab.yaml` 或 Graphify 派生正文；不引入外部论文搜索。
- 未跟踪的 `智能问答交接文档-2026-08-12.md` 不纳入提交。

## Acceptance Criteria

- [ ] 不存在针对“波干扰”等完整问题短语的检索分支；多个不同主题及中英文改写测试均通过同一查询规划器召回相应本地证据。
- [ ] 单次请求最多三轮检索；充分证据、无新增扩展和低增益均能确定性停止，诊断不包含敏感/原始查询内容。
- [ ] 同一回答可同时保存逐句引用的验证内容与明确标识的模型补充，状态为 `mixed`；未标识无引用事实继续失败。
- [ ] `mixed` 回答重新打开后完整可见，但其模型补充不进入后续可信上下文；纯 supported 与零证据行为不退化。
- [ ] `entailmentChecked=false`，界面仍显示语义未自动核验。
- [ ] Codex 持续输出活动超过旧 90 秒时不被误杀；真正静默与绝对超时分别返回稳定错误码，取消仍快速生效。
- [ ] 聊天输入区可以选择本机检测到的 GPT/Codex 模型和该模型真实支持的 reasoning effort，并在当前请求中使用正确快照。
- [ ] 设置页不再重复展示模型/effort；标题状态与 composer 控件符合现有蓝灰紧凑风格。
- [ ] 缺失/损坏模型缓存、未知旧模型、空默认值、模型切换 effort 回退均有测试，DTO 无认证秘密。
- [ ] Rust 定向/全量测试、前端测试与构建、fmt、Clippy、P3/P5、Wiki lint、`git diff --check` 全部通过。
- [ ] 成功提交 Git 并生成可运行桌面构建；用户未跟踪交接文档不进入提交。

## Out of Scope

- 引用—结论语义蕴含/NLI 审计。
- 展示或持久化模型隐藏 chain-of-thought。
- 外部联网论文搜索、自动下载或自动修改知识库正文。
- 取消现有引用覆盖门禁或自动为无引用事实猜测来源。
- 直接复制 CPA/Sub2API 的认证、代理或计费逻辑；仅在本机 Codex 元数据不足时借鉴其模型能力投影思路。
