# 智能问答功能业务逻辑与优化审查

## Goal

对桌面端 0.12.3 的智能问答功能执行一次只读、证据化审查，向用户说明完整业务逻辑、当前优势、仍存在的缺点与风险，并给出按业务价值和实施成本排序的优化路线。

## Background

- 0.12.3 已修复上一轮确认的五项 P1：历史感知 RetrievalQuery、零证据 unverified、即时取消与 blocking retrieval、失败交换成对持久化、Graphify relation/neighbor 召回。
- 当前功能本质仍是“本地多通道关键词检索 + 规则排序 + 受编号证据约束的模型生成”。
- 现有自动化证明固定 Wiki/paper 召回 10/10、两书 Recall@5 为 1.000000 / 0.986667，但尚未等价证明真实模型回答的事实准确率、claim-level 引用覆盖率或幻觉率。

## Requirements

1. 从前端提交开始，覆盖 request ID、会话历史、query rewrite、多路检索、排序组包、回答引擎、流事件、引用校验、持久化、取消、失败重试和 repository switch。
2. 区分业务层、数据层、检索层、生成层、可信度层和交互层，说明各层输入、输出与边界。
3. 所有关键判断以当前源码、测试、Trellis QA 契约和既有评测为依据；旧审查中已修复的问题不得继续列为当前缺陷。
4. 对每项缺点说明影响、触发场景、严重度、当前保护措施和建议方案。
5. 优化建议按“科研可信度、检索质量、用户体验、性能与运维”分类，并给出推荐优先级、收益、复杂度和依赖。
6. 审查保持只读：不修改产品代码、Raw/Wiki/Graphify 正文、正式词表或 B 类页面，不默认外搜。

## Acceptance Criteria

- [x] 输出一条可读的端到端业务流程，并说明三种回答引擎和零证据分支。
- [x] 准确描述 completed、unverified、failed、cancelled 四类终态如何进入或排除历史。
- [x] 列出当前已解决的可靠性能力，避免把 0.12.3 修复项误判为遗留缺陷。
- [x] 至少识别 5 个仍存在的、有源码证据的优化点，并区分缺陷、能力边界与扩展建议。
- [x] 给出分阶段优化路线和推荐的下一批 MVP，不直接实施改动。
- [x] 关键结论引用当前绝对文件路径与行号，报告注明当前库水位和自动化能证明/不能证明的范围。

## Out of Scope

- 本轮不修改代码、不新增测试、不构建安装包。
- 不对真实 Codex/API 发起付费或外部模型请求。
- 不重新生成 Graphify，不修改知识库内容治理结构。
